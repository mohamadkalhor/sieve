Seat efforts

Every seat gets one new setting, Runs at: the reasoning effort its agent actually uses. Sieve then scores each model at that effort instead of at its best one, and shows the effort on every row and the whole effort ladder in the inspector.

Why: Sieve scores today's seats at the wrong effort

Artificial Analysis publishes one row per effort, and Sieve already keeps them apart. But a router id such as cx/gpt-6-astra names no effort, so it matches the family's bare row, which is its top mode. Hermes then calls it at the profile's reasoning_effort. The build seat runs at medium and is ranked at max.

This is live, not hypothetical: 15 of the shipped LLM seats have a multi-effort model in their list, and 11 of them have one as their first pick, build included.

What the fix does

Astra loses 3 points, Sol loses 8. A model whose ladder is flat (Astra on coding: 76.9 at max, 76.7 at medium) barely moves. A model that leans on high effort drops. The list reorders to what the seat really gets.

Price per token is the same at every effort. Higher modes burn more output tokens, which no source we read publishes, so per-task cost still cannot tell modes apart. The plan keeps saying so on the page.

3 · Phone and the Field page

On a phone, Runs at is one 44px row that opens a sheet of efforts. The pill wraps under the model name with the score, so nothing is clipped at 375px.

The Field page already joins a family's efforts into a line. It gains one mark: when you arrive from a seat, the point at that seat's effort is ringed in the accent, so you can see where on the line the seat sits.

The command palette gets effort medium (and the other efforts) for the open seat.

4 · Back end and front end

One rule holds the design together: the row's id never changes with effort. Pins, removals, manual lists, chains and router ids stay keyed on the model the router reaches. Effort only changes which published row is read to score it. So switching a seat from medium to high cannot lose a pin, and what ships to 9router is the same list of router ids.

5 · How it gets built

Contracts first, then one serial chain of AMS cards on Opus 5.5 at medium effort, in its own working copy on a new branch effort so it cannot collide with the agent-io (D1) work landing on main. I verify each card on the branch before the next one starts.

6 · Decided, and what to tell me if you disagree

  • Nearest below, not above. When a family skips the seat's effort, scoring falls to the lower one. Under-crediting is the safe error; over-crediting is the bug this fixes.
  • One effort per seat, not per model. Hermes sets reasoning_effort per profile, so that is the true granularity. A per-model override can come later if a router starts honouring effort per id.
  • Default stays any on deploy, so nothing moves until a seat is set. After you approve, I set the live seats from their Hermes profiles in one step: assistant, build, cataloguer, creator, manager at medium; coordinator at high. The rest show effort? until you pick.
  • Media seats get no control; efforts are an LLM thing and a hidden setting rots.
